## 这个产品是什么

心履网站是**服务端渲染**的（Django 读库出 HTML），同时对外提供一套 REST API
给三个原生客户端用。另外它会**服务端到服务端**地调用 phix（统一账号、跨站免密登录、
资料对象同步）。生产在 `192.168.5.35` 的 `xinlv.service`，经 Cloudflare Tunnel
暴露为 `https://xin-lv.com`。

## 工程约定（请遵守）

- **注释和提交信息用中文**，写**为什么**。
- 错误要**如实**：用 `_err("中文说明", 状态码)` 让客户端能直接展示给用户。
- **限流是进程内存实现**，单进程 waitress 够用；**换多进程部署必须重写**。
  写测试时每个用例前 `ratelimit._hits.clear()`。
- **写入要原子**（临时文件 + rename）；**改模板必须重启 waitress**，否则一直发旧页面。
- AI 调用有安全边界（`core/ai_security.py`），**不要绕过**。
- 网页端是给普通用户看的：**不要在界面上展示服务器地址、密钥、同步游标**这类技术细节
  （用户明确要求过）。作者信息、版本号、官网链接是要展示的。

### ⚠️ 线程数与长轮询名额必须成对配置

长轮询会把请求挂住最多 25 秒，而 waitress 一个挂起就**占一个线程**。
生产是 drop-in 里的 `--threads=32` + `MOODTREE_WATCH_SLOTS=8`，
**这两个数不在仓库里**（在服务器的 systemd 单元里）。
代码里的默认名额是 2（按 waitress 默认 4 线程保守取值）。
**改的时候必须成对改**：名额比线程数大 = 挂起把线程池占满 = 整站卡死。

⚠️ `D:\moodsite\deploy_sync.py` 是**一次性旧脚本**（写死了 1.1.5/1.2.31），**别用它部署**。
